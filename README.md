# 유튜브 재생목록 북마크

YouTube 재생목록(`youtube.com/playlist?list=...`)에 **북마크**를 만들어 두고,
화면 위쪽(왼쪽/오른쪽) 패널에서 클릭하면 그 영상으로 **점프**합니다. 재생목록에 이미 있는 영상을
원하는 북마크 **바로 밑으로 옮길** 수도 있습니다.

수백~수천 곡짜리 긴 재생목록을 구간별로 나눠 쓰기 위한 도구입니다.

> 이 프로젝트를 이어받는다면 맨 아래 **[인수인계서](#인수인계서)** 부터 보세요.

**설정 없이 바로 되는 기능**: 북마크 만들기 · 점프 · 검색 · 이름 바꾸기 · 한 칸 이동 ·
목록 순서 바꾸기 · 삭제 — 전부 이 PC 로컬 저장만 씁니다.
**구글 로그인이 필요한 기능**: 영상을 북마크 밑으로 이동(`↦북마크`) — 실제 재생목록
순서를 바꾸는 쓰기 작업이라 YouTube Data API 가 필요하고, 그건 구글 정책상 로그인
없이는 불가능합니다.

## 설치

1. 주소창에 `edge://extensions` (크롬은 `chrome://extensions`) 입력
2. **개발자 모드** 켜기
3. **압축해제된 확장 프로그램 로드** → 압축을 푼 이 폴더 선택
   (업데이트할 때는 같은 폴더의 파일만 덮어쓰고 확장 목록에서 ↻ 새로고침 — 북마크·설정은
   `manifest.json` 의 `key` 로 고정된 확장 ID 에 저장되므로 그대로 유지됩니다.
   확장을 "삭제" 하면 저장된 북마크·로그인 설정도 같이 지워지니 삭제 후 재설치는 피하세요)
4. `youtube.com/playlist?list=...` 페이지로 이동

`↦북마크`(영상 이동)를 쓰려면 아래 [구글 로그인 설정](#구글-로그인-설정-영상-이동용)을
한 번 해 주세요. 나머지 기능은 로드하자마자 바로 됩니다.

## 사용법

### 북마크 만들기 · 점프
- 영상에 마우스를 올리면 뜨는 **`＋북마크`** → 이름 입력 → Enter
- 우측 패널에서 북마크를 클릭하면 그 영상으로 스크롤 (아직 로딩 안 된 아래쪽이면 자동으로 로딩하며 찾아감)
- 패널의 북마크 줄을 **끌어서 놓으면 목록 순서**가 바뀝니다 (저장된 순서만 바꾸는 로컬 작업)
- 북마크 기준 영상이 재생목록에서 **삭제되면 바로 앞 영상이 그 북마크를 물려받습니다** (150번째가 없어지면 149번째)
- `↦북마크` 로 영상을 보낸 직후에는 패널 **헤더에 `⟳` 경고 배지**가 켜집니다 (클릭 = 새로고침). 패널을 접어도 보입니다
- 패널 맨 위에는 **"↩ 방금 옮긴 영상으로"** 줄이 떠서, 누르면 그 영상으로 갑니다 (10분간)

> **왜 새로고침이 필요한가**: `↦북마크` 는 YouTube Data API 로 서버의 재생목록 순서를
> 바꿉니다. 그런데 지금 화면에 떠 있는 유튜브 목록은 **옛 순서 그대로**이고, 유튜브는
> 영상을 지우거나 드래그할 때 그 옛 상태를 기준으로 처리합니다. 그래서 옮긴 직후에
> 삭제하면 엉뚱한 영상이 지워지거나 다른 영상이 그 자리로 밀려 들어옵니다. 확장이
> 유튜브 내부의 목록 상태를 고쳐 줄 방법은 없어서, 새로고침으로만 풀립니다.
> 새로고침하면 경고 줄은 사라집니다.
- 패널과 hover 도구막대는 유튜브 항목 오른쪽 끝의 `⋮`(더보기) 버튼 열을 덮지 않도록 항상 그 왼쪽에 붙습니다
- 패널 헤더의 `⤒`/`⤓` 는 재생목록 맨 처음/맨 끝으로 이동합니다 (패널을 접어도 보입니다)
- 헤더의 `◤` `◥` 로 패널을 왼쪽 위 / 오른쪽 위에 둡니다 (지금 위치는 버튼이 노랗게 표시되고, 선택은 저장됩니다)
- 왼쪽 위치는 유튜브 본문(재생목록 헤더 카드·영상 목록) 왼쪽의 빈 여백에 들어갑니다. 여백이 좁으면 패널이 그만큼 좁아집니다
- **`⤒ 맨 처음` / `⤓ 맨 끝`** 은 항상 표시되는 기본 북마크

### 패널의 각 북마크 행 버튼

| 버튼 | 기능 |
|---|---|
| `▲` `▼` | 북마크를 **한 칸 위/아래 영상**으로 옮김 (미세 조정) |
| `✎` | **이름 바꾸기** |
| `🗑` | 북마크 삭제 |

> `⤓`(맨 끝)과 자동 로딩은 페이지 맨 아래가 아니라 **목록 끝의 "이어 불러오기" 표시**를
> 화면에 넣는 방식으로 스크롤합니다. 페이지 맨 아래로 내리면 재생목록 밑에 붙은
> "추천 재생목록" 영역으로 내려가 버려서 목록이 중간에서 멈춥니다.

> `▲▼` 는 **화면에 로딩된 영상** 안에서만 움직입니다. "기준 영상이 아직 로딩 안 됐어요"가
> 뜨면 자동으로 스크롤하며 찾은 뒤 이동합니다.

### 영상을 북마크 밑으로 이동 (구글 로그인 필요)
- 영상에 마우스를 올려 **`↦북마크`** → 보낼 북마크 선택
- 연달아 보내면 **보낸 순서 그대로** 쌓입니다
- 처음 누르면 구글 로그인 창이 한 번 뜹니다 (아래 설정 필요)
- 재생목록 자체의 순서는 즉시 바뀝니다. 화면에서는 옮긴 영상이 **원래 자리에서
  사라지고**, 기준 영상이 화면에 있으면 그 줄이 잠깐 강조됩니다. 새 자리의 모습은
  그 구간이 로딩될 때(스크롤) 또는 새로고침하면 보입니다.
  - 확장은 유튜브 목록의 **순서를 직접 바꾸지 않습니다**. 예전에는 옮긴 영상을 기준
    영상 뒤로 끌어다 붙여 바로 쌓이는 모습을 보여 줬는데, 그건 유튜브 자신의 목록
    컴포넌트가 관리하는 자식 순서를 건드리는 일이라 이어 불러오기가 엉켜 **무한
    로딩**이 났습니다. 지금은 클래스 하나로 숨기기만 합니다.
  - 아래쪽을 대신 더 로딩하지도 않습니다 — 유튜브는 한 번 로드한 항목을 다시 비우지
    않아서, 이동할 때마다 수백 개씩 더 로딩하면 그 뒤로 재생목록을 볼 때마다 계속
    느려지기 때문입니다(아래 성능 설계 참고).

### 다른 재생목록의 북마크 삭제
패널 맨 위 재생목록 이름을 클릭하면 북마크를 만들어 둔 다른 재생목록 목록이 펼쳐집니다.
각 항목 옆 `✕` 를 누르면 그 재생목록의 북마크를 전부 지울 수 있습니다 — 재생목록 자체가
삭제됐거나 더 이상 안 쓸 때 정리하는 용도입니다.

### 검색
패널 검색창에 `노래제목 / 가수` 형식으로 입력하면 화면에 로딩된 영상 안에서 찾아줍니다.
아래로 스크롤해 영상이 더 불려오면 그것까지 포함해 다시 찾습니다.

## ⚙ 구글 로그인 설정 (영상 이동용)

패널 오른쪽 위 **`⚙`** 버튼으로 엽니다. `↦북마크` 말고 다른 기능은 이 설정이 없어도
전부 동작합니다.

⚙ 모달 안에 **"📖 사용법"** 접이식 안내가 있고, 각 단계로 바로 가는 링크가 들어 있습니다.
눌렀을 때만 펼쳐집니다. 아래는 같은 내용입니다.

1. [구글 클라우드 콘솔](https://console.cloud.google.com/projectcreate) → 프로젝트 만들기
2. **API 사용 설정** → [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com)
3. **OAuth 동의 화면** 구성 → 사용자 유형 `외부` → **테스트 사용자**에 본인 구글 계정 추가
4. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 유형: `웹 애플리케이션`**
5. **승인된 리디렉션 URI** 에 확장의 리디렉션 URI 등록
   - 값은 ⚙ 모달에 표시됩니다 (`복사` 버튼 있음). 형태: `https://<확장ID>.chromiumapp.org/`
6. 만들어진 **클라이언트 ID** 를 ⚙ 모달에 붙여넣고 **저장**
7. **구글 로그인** 버튼 클릭 → 완료

> 클라이언트 ID 는 이 PC 의 확장 저장소에만 있습니다. 확장을 **삭제 후 재설치**하면
> 북마크와 함께 지워지므로 다시 넣어야 합니다(파일만 덮어쓰고 ↻ 새로고침하면 유지).
> ID 가 비어 있는 상태로 `↦북마크` 를 누르면 ⚙ 모달이 바로 열립니다.
>
> 여러 사람에게 배포하면서 매번 입력하지 않게 하려면 `background.js` 맨 위쪽
> `DEFAULT_CLIENT_ID` 에 본인 클라이언트 ID 를 넣어 두면 됩니다(⚙ 입력값이 있으면
> 그게 우선). 할당량(하루 10,000유닛 ≒ 이동 200회)은 그 프로젝트 하나로 합산됩니다.

> **로그인 유지 요약**
>
> | 설정 | 다시 로그인하는 빈도 |
> |---|---|
> | secret 없음 (기본) | 브라우저 재시작·장시간 경과 시 가끔 |
> | secret 입력 + 동의 화면 `테스트` | 약 7일마다 (구글이 갱신 토큰을 7일 뒤 만료시킴) |
> | secret 입력 + 동의 화면 `프로덕션` | 사실상 없음 |
>
> 프로덕션 전환은 [대상(게시 상태)](https://console.cloud.google.com/auth/audience) 에서
> **앱 게시** 를 누르면 됩니다. 심사 없이 게시해도 되고, "확인되지 않은 앱" 경고는 그대로입니다.

**로그인 유지**: 기본값은 액세스 토큰 1시간짜리 + refresh token 없음입니다. 만료되면
먼저 팝업 없이 조용한 갱신을 시도하고, 그게 안 될 때만(예: 브라우저의 제3자 쿠키 차단
등으로 막힌 경우) `↦북마크`를 다시 누를 때 로그인 창이 한 번 더 뜰 수 있습니다.

PC를 껐다 켜도 로그인이 계속 유지되길 원하면, ⚙ 모달의 **"OAuth 클라이언트 보안
비밀번호(secret)"** 칸에 클라이언트 시크릿도 넣으세요(사용자 인증 정보 페이지의 그
클라이언트 상세에서 확인/재생성 가능). 이걸 넣으면 refresh token 을 받아 저장해 두고,
액세스 토큰이 만료돼도 팝업 없이 자동으로 갱신합니다. 구글이 "웹 애플리케이션"
클라이언트의 refresh token 발급에는 client_secret 을 요구해서(PKCE 만으로는 면제되지
않음) secret 없이는 이 경로를 쓸 수 없습니다 — 그래서 선택 항목으로 뒀습니다.
비워두면 지금처럼(시크릿 없이) 동작합니다.

> secret 은 client ID 보다 조금 더 민감한 값이라 이 PC의 확장 저장소에 그대로
> 저장됩니다. 본인만 아는 개인 프로젝트의 값이라 위험도는 낮지만, 원치 않으면
> 비워두세요 — 로그인 자체는 secret 없이도 항상 됩니다.

**할당량**: 하루 10,000 유닛. 영상 이동이 회당 50 유닛이므로 하루 약 200회.
각자 본인 프로젝트를 쓰므로 다른 사용자와 할당량을 나눠 쓰지 않습니다.

### 다른 사람에게 배포할 때

이 확장은 **각 사용자가 본인 구글 API 를 넣어 쓰는 구조**입니다.

`manifest.json` 에는 **클라이언트 ID 항목 자체가 없습니다.** 개인 정보가 들어 있지 않으니
폴더를 그대로 압축해 배포해도 됩니다. 각 사용자는 ⚙ 모달에서 본인 클라이언트 ID 를 넣습니다.

> `oauth2` 키를 manifest 에 다시 넣지 마세요. 그건 크롬 전용 `getAuthToken` 방식용이고,
> 이 확장은 엣지에서도 되는 `launchWebAuthFlow` 를 씁니다.
> 특히 `"client_id": ""` 처럼 빈 값을 넣으면 **확장이 아예 로드되지 않습니다**
> (`Invalid value for 'oauth2.client_id'`).

`manifest.json` 의 `key` 필드는 **그대로 두세요.** 이건 비밀키가 아니라 **공개키**이며,
확장 ID를 고정해서 모든 사용자가 동일한 리디렉션 URI 를 쓰게 해 줍니다(안내가 단순해짐).

> 참고: 구글 OAuth 검증을 받지 않은 앱이므로 사용자에게 "확인되지 않은 앱" 경고가
> 표시됩니다. 본인 프로젝트에서 본인이 테스트 사용자이므로 `고급 → 계속`으로 진행하면 됩니다.

## 성능 설계 (건드리면 안 되는 원칙)

긴 재생목록에서 무한 로딩·렉이 나던 문제를 해결하며 정해진 규칙입니다.

1. **유튜브 재생목록 DOM 에 쓰지 않는다.** 영상 항목에 노드를 넣거나 속성을 붙이면
   유튜브의 lazy-load 와 충돌해 무한 로딩이 발생합니다. 확장 UI 는 전부 별도 레이어
   (패널·플로팅 도구막대·모달)에 그립니다.
2. **재생목록을 상시 감시하지 않는다.** MutationObserver 로 목록을 지켜보지 않습니다.
3. **평소에 DOM 을 읽지 않는다.** 패널은 저장된 데이터만으로 그립니다.
   목록 조회는 점프·`▲▼`·`↦북마크` 처럼 **클릭했을 때만 1회**.
4. **`getBoundingClientRect` 를 반복 호출하지 않는다.** 강제 레이아웃이 잔렉의 원인이라,
   도구막대 위치는 마우스가 다른 영상으로 넘어갈 때만 1회 측정합니다.
5. **줄 엘리먼트에 값을 캐시하지 않는다.** 유튜브는 순서를 바꿀 때 줄 엘리먼트를
   재활용하므로, 엘리먼트에 영상 ID 를 기억해 두면 옮긴 뒤 엉뚱한 영상을 가리킵니다
   (목록이 "섞이거나 몇 개가 안 보이던" 원인). 검색 목록만 **로드된 줄 수**를 함께
   기억해 두고, 그 수가 달라지면 통째로 다시 만듭니다.

이 원칙을 어기는 기능(재생목록 안에 그리는 인라인 구분선, 드래그 앤 드롭,
실시간 곡 수 카운트)은 렉을 되살립니다.

> 렉은 **파일 용량이 아니라 DOM 을 얼마나 자주/많이 건드리느냐**에서 옵니다.
> `content.js` 가 몇십 KB 늘어나는 건 브라우저가 파싱하는 데 밀리초 단위라 체감되지
> 않고, `background.js`(로그인·API 호출)는 아예 페이지에 들어가지 않는 별도
> 서비스 워커라 유튜브 페이지 성능과 무관합니다.
>
> 무한 로딩도 한 번 있었습니다: `↦북마크` 뒤에 옮긴 영상 노드를 기준 영상 뒤로
> 끌어다 붙였더니(유튜브 목록의 자식 순서 변경), 유튜브의 이어 불러오기가 엉켜
> 영상 하나만 옮겨도 로딩이 멈추지 않았습니다. 지금은 유튜브 DOM 의 **구조는 전혀
> 건드리지 않고** 숨김 클래스만 붙입니다.
>
> 그리고 실제로 렉을 만든 적이 두 번 있습니다. 둘 다 `↦북마크`가 반영 안 된 기준
> 영상을 찾겠다고 스스로 아래쪽을 스크롤해 로딩하게 했을 때입니다 — 처음엔 "점프"처럼
> **무제한으로**, 그다음엔 짧은 상한(약 4초)을 두고. 상한을 둬도 이동 한 번에
> 수백 개씩 더 렌더링됐고, 유튜브는 한 번 로드한 항목을 다시 비우지 않아서 그 뒤로는
> 확장을 안 써도 재생목록을 스크롤할 때마다 계속 느려졌습니다. 게다가 API 로 순서를
> 바꾼 **뒤에** 아래쪽을 로딩하면 유튜브가 새 순서대로 그 영상을 다시 그리는데,
> 원래 노드도 남아 있어서 같은 영상이 두 개씩 보였습니다. 그래서 지금은 `↦북마크`가
> 아래쪽을 전혀 로딩하지 않고, 기준 영상이 안 보이면 원래 노드를 숨기기만 합니다
> (위 "영상을 북마크 밑으로 이동" 참고). "점프"·`▲▼`는 원래부터 사용자가 그 자리를
> 직접 지목해 누른 동작이라 상한 없이 끝까지 찾는 게 맞다고 보고 그대로 뒀습니다.

없고(로그인 시 구글 서버와의 OAuth 통신만 예외), 동기화·백업파일 기능은 없습니다.

이 확장을 처음 맡는 사람(또는 다음 작업 세션)이 알아야 할 것만 적습니다.
설치·사용법·구글 로그인 절차·성능 원칙·저장 키는 **위 항목들에 이미 있으니 여기서는
반복하지 않고**, 위에 없는 것만 둡니다 — 지금 상태, 그렇게 정한 이유, 실제로 물렸던
함정, 남은 일.

> **갱신 규칙**: 작업할 때마다 이 절에서 **달라진 것만** 고칩니다. 새 내용이 위
> 항목들에 들어갈 성격이면 거기에 쓰고 여기엔 적지 않습니다. 같은 말을 두 곳에
> 두지 않는 것이 이 문서의 유일한 규칙입니다.

### 이어서 시작할 때 (제일 먼저 볼 것)

```
git log --oneline -5                     # 어디까지 했는지
grep -n 'DEFAULT_CLIENT_ID = ' background.js   # = "";  이어야 한다
node tools/smoke-test.js                 # 27개 통과하면 지금 상태가 멀쩡하다는 뜻
```

이 셋이 깨끗하면 코드는 건드릴 게 없는 상태입니다. 그 다음은 "지금 상태" 표의
**남은 일** 과 아래 **확인 대기** 만 보면 됩니다.

**확인 대기 (소유자만 할 수 있는 것)**

- 동의 화면을 프로덕션으로 바꾼 **뒤에** ⚙ 에서 한 번 `로그아웃 → 구글 로그인` 을
  했는지. 프로덕션 전환 전에 받은 갱신 토큰은 여전히 7일짜리라, 이걸 안 하면
  일주일 뒤 로그인 창이 다시 뜹니다. 뜨면 이것부터 시키세요.
- 소유자가 쓰는 확장이 최신 버전인지. ⚙ 모달의 시크릿 칸 위 설명이 "테스트 상태면
  7일마다" 를 언급하지 않으면 4.10.1 이전 버전입니다.

**열려 있는 결정**

- 확장 아이콘: 없어도 동작해서 미뤄 둔 상태. 소유자가 "굳이 해야 하냐" 고 물었고
  "안 해도 된다" 로 답해 뒀습니다. 툴바에 고정해 쓰기 시작하면 그때 만들면 됩니다.
- 저장소 공개 전환: 지금은 필요 없습니다. 구글이 정책 링크를 요구할 때만.

### 배포 규칙 (반드시 지킬 것)

1. 저장소의 `background.js` 안 `DEFAULT_CLIENT_ID` 는 **항상 빈 문자열**입니다.
   커밋 전에 `grep -n 'DEFAULT_CLIENT_ID = ' background.js` → `= "";` 확인.
2. 소유자에게 보내는 zip **에서만** 그 자리에 소유자 클라이언트 ID 를 넣고,
   `manifest.json` 의 `name` 뒤에 ` (개인용)` 을 붙입니다.
   파일 이름은 항상 `유튜브 플레이리스트 북마크.zip`.
3. zip 안의 폴더 이름은 **ASCII** 로 합니다. 한글 폴더명으로 압축하면 윈도우에서 풀 때
   "폴더가 비어 있음" 으로 보입니다(실제로 겪음). 지금은 `Youtube-playlist-bookmark`.
4. zip 에는 확장 파일만 담습니다 — `tools/` 와 `.git` 은 뺍니다.
5. **클라이언트 시크릿은 저장소에도, 대화에도 남기지 않습니다.** 소유자가 ⚙ 모달에
   직접 넣는 값이고, 구글 콘솔도 코드 저장소 보관을 금지합니다.

### 구글 OAuth 현황

- 동의 화면은 **프로덕션**으로 게시돼 있습니다. **테스트** 상태일 때는 구글이 갱신
  토큰을 7일 뒤 만료시켜서 일주일에 한 번 로그인 창이 떴습니다. 로그인이 다시 자꾸
  뜬다는 얘기가 나오면 게시 상태부터 확인하세요.
- 심사는 받지 않았으므로 "확인되지 않은 앱" 경고는 계속 뜹니다(고급 → 이동). 정상입니다.
- 게시에 필요한 개인정보처리방침·이용약관은 `PRIVACY.md` / `TERMS.md` 로 저장소에
  있습니다. 저장소가 비공개라 구글이 **링크**를 요구하면, 저장소를 공개로 바꿔
  `/blob/main/PRIVACY.md` 를 쓰거나 공개 Gist 로 복사해야 합니다(아직 안 함).
- 하루 한도는 영상 이동 약 200회입니다(10,000유닛 ÷ 50유닛).

### 고칠 수 없는 것 (버그가 아니라 한계)

- `↦북마크` 로 순서를 바꾸면 **화면에 떠 있는 유튜브 목록은 옛 순서 그대로**입니다.
  유튜브가 들고 있는 내부 목록을 확장이 고쳐 줄 방법이 없어서, 그 상태로 영상을
  지우거나 끌면 엉뚱한 영상이 지워집니다. 그래서 패널 헤더에 ⟳ 경고 배지를 띄우고
  새로고침을 권합니다. 새로고침 말고는 방법이 없습니다.
- 검색은 **화면에 로드된 부분**만 봅니다. 전체를 훑으려면 API 를 써야 하는데
  할당량을 먹습니다.
- 모바일에서는 동작하지 않습니다. 확장은 `www.youtube.com` 에만 붙고 폰은
  `m.youtube.com` 으로 갑니다.

### 물렸던 함정 (다시 밟지 말 것)

성능 관련은 위 "성능 설계" 절에 있고, 여기는 그 밖에 실제로 터졌던 것들입니다.

- **`.ytpd-pos-tl` / `.ytpd-pos-tr` CSS 를 "안 쓰는 규칙" 이라고 지우지 마세요.**
  `applyPanelPos` 가 `"ytpd-pos-" + 값` 으로 조립해 붙이기 때문에 JS 에 그 이름이
  글자 그대로 나오지 않습니다. 자동으로 죽은 CSS 를 찾는 스크립트에 지워진 적 있습니다.
- **함수를 `addEventListener` 에 그대로 넘기지 마세요.** `openMiniSettings` 를 그렇게
  넘겼더니 클릭 이벤트가 첫 인자(오류 메시지) 자리에 들어가
  "로그인 안 됨 — [object PointerEvent]" 가 떴습니다. `() => openMiniSettings()` 로 감쌉니다.
- **왼쪽 패널 위치를 계산할 때 헤더 rect 를 맹신하지 마세요.** 재생목록 헤더가
  화면을 가로지르는 배너형이면 left 가 0 이라 계산이 통째로 건너뛰어지고, 패널이
  기본 좌표에 남아 영상 목록을 덮습니다(4.10.2 에서 고침).
- **`disableUI` 로 페이지에서 떼어 낸 도구막대를 "변수가 있으니 됐다" 로 건너뛰지
  마세요.** 팝업으로 껐다 켜면 새로고침 전까지 도구막대가 안 돌아왔습니다.
- **`init` 은 겹쳐 돌 수 있습니다.** 재생목록을 빠르게 옮기면 앞선 `init` 이 저장소
  응답을 기다리는 사이 다음 `init` 이 시작돼, 앞 재생목록의 북마크가 다음 재생목록
  키에 저장될 수 있었습니다. 지금은 `await` 마다 자기 차례인지 확인합니다.
- **커밋했다고 믿지 말고 `git log` 로 확인하세요.** `node -e '...' && git commit` 형태로
  묶었다가 앞 명령이 실패해 커밋이 조용히 건너뛰어진 적 있습니다.

가로채므로 네트워크도 로그인도 필요 없습니다. 마지막 측정값(CPU 6배 느리게, 영상 3000개):
스크롤 프레임 중앙값 16.6ms 로 확장 없을 때와 같고, 50ms 넘게 멈춘 프레임 0개,
hover 0.12ms/회.

> 테스트를 고칠 때 주의: 브라우저는 마우스가 **이미 그 줄 위에 있으면** `pointerover`
> 를 새로 쏘지 않습니다. 줄에 마우스를 올리는 검사 앞에는 `page.mouse.move(5, 5)` 로
> 바깥에서 들어오는 움직임을 만들어 줘야 합니다. 이걸 몰라서 멀쩡한 코드를 버그로
> 의심한 적 있습니다.
