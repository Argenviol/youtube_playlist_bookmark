# 유튜브 재생목록 북마크

YouTube 재생목록(`youtube.com/playlist?list=...`)에 **북마크**를 만들어 두고,
우측 패널에서 클릭하면 그 영상으로 **점프**합니다. 재생목록에 이미 있는 영상을
원하는 북마크 **바로 밑으로 옮기거나**, URL/ID 로 새 영상을 그 자리에 **추가**할 수 있습니다.

수백~수천 곡짜리 긴 재생목록을 구간별로 나눠 쓰기 위한 도구입니다.

## 설치

1. 주소창에 `edge://extensions` (크롬은 `chrome://extensions`) 입력
2. **개발자 모드** 켜기
3. **압축해제된 확장 프로그램 로드** → 이 `Youtube-playlist/` 폴더 선택
4. `youtube.com/playlist?list=...` 페이지로 이동

**설정 없이 바로 되는 기능**: 북마크 만들기 · 점프 · 검색 · 이름 바꾸기 · 한 칸 이동 · 삭제
**구글 API 설정이 필요한 기능**: 영상 이동(`↦북마크`) · 영상 추가(`＋`) · 기기 간 동기화

---

## 사용법

### 북마크 만들기 · 점프
- 영상에 마우스를 올리면 뜨는 **`＋북마크`** → 이름 입력 → Enter
- 우측 패널에서 북마크를 클릭하면 그 영상으로 스크롤 (아직 로딩 안 된 아래쪽이면 자동으로 로딩하며 찾아감)
- **`⤒ 맨 처음` / `⤓ 맨 끝`** 은 항상 표시되는 기본 북마크

### 패널의 각 북마크 행 버튼

| 버튼 | 기능 |
|---|---|
| `▲` `▼` | 북마크를 **한 칸 위/아래 영상**으로 옮김 (미세 조정) |
| `✎` | **이름 바꾸기** |
| `＋` | 이 북마크 밑에 URL/ID 로 영상 추가 |
| `이동` | 멀리 있는 영상으로 옮기기 — 누른 뒤 대상 영상의 `📍여기로` 클릭 (Esc 취소) |
| `✕` | 북마크 삭제 |

> `▲▼` 는 **화면에 로딩된 영상** 안에서만 움직입니다. "기준 영상이 아직 로딩 안 됐어요"가
> 뜨면 그 위치까지 스크롤한 뒤 다시 누르세요.

### 영상 정리
- 영상에 마우스를 올려 **`↦북마크`** → 보낼 북마크 선택
- 연달아 보내면 **보낸 순서 그대로** 쌓입니다

### 검색
패널 검색창에 `노래제목 / 가수` 형식으로 입력하면 재생목록 안에서 찾아줍니다.

---

## ⚙ 설정 탭

패널 오른쪽 위 **`⚙`** 버튼으로 엽니다.

### 기기 간 동기화

구글 로그인을 하면 북마크가 **내 구글 드라이브의 앱 전용 폴더**에 저장되어, 다른 PC 에서
같은 구글 계정으로 로그인했을 때 같은 북마크를 볼 수 있습니다.

- **로그인하지 않아도** 그 PC 안에서는 모든 기능이 그대로 동작합니다 (로컬 저장)
- 브라우저 계정(엣지 계정)이 PC 마다 달라도 상관없습니다 — **구글 계정만 같으면** 됩니다
- `동기화 사용` 체크 → 북마크가 바뀔 때마다 자동으로 올라갑니다 (3초 묶음 처리)
- `지금 불러오기` — 다른 PC 에서 바꾼 내용을 즉시 가져옴
- `지금 올리기` — 이 PC 내용을 즉시 올림

**합치기 규칙**: 양쪽 내용을 합집합으로 합칩니다(아무것도 사라지지 않음). 같은 북마크가
양쪽에 있으면 더 최근에 수정된 쪽을 씁니다. 같은 영상에 북마크가 둘 생기면 하나만 남깁니다.

> 앱 전용 폴더는 이 확장이 만든 파일만 보이는 공간이라, 확장이 사용자의 다른
> 드라이브 파일에 접근할 수 없습니다.

### 내 구글 API

영상 이동·추가·동기화를 쓰려면 본인 구글 클라우드의 OAuth 클라이언트 ID가 필요합니다.
아래 설정을 한 번만 하면 됩니다.

1. [구글 클라우드 콘솔](https://console.cloud.google.com/) → 프로젝트 만들기
2. **API 사용 설정**
   - [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com) — 영상 이동/추가용
   - [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com) — 동기화용 (동기화 안 쓰면 생략 가능)
3. **OAuth 동의 화면** 구성 → 사용자 유형 `외부` → **테스트 사용자**에 본인 구글 계정 추가
4. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 유형: `웹 애플리케이션`**
5. **승인된 리디렉션 URI** 에 확장의 리디렉션 URI 등록
   - 값은 ⚙ 설정 탭에 표시됩니다 (`복사` 버튼 있음). 형태: `https://<확장ID>.chromiumapp.org/`
6. 만들어진 **클라이언트 ID** 를 ⚙ 설정 탭에 붙여넣고 **저장**
7. 패널에서 로그인 → 완료

**할당량**: 하루 10,000 유닛. 영상 이동/추가가 회당 50 유닛이므로 하루 약 200회.
각자 본인 프로젝트를 쓰므로 다른 사용자와 할당량을 나눠 쓰지 않습니다.

## 백업 / 복원

북마크는 브라우저 내부 저장소(LevelDB)에 저장되어 **폴더를 열어도 읽을 수 없는 형식**입니다.
그래서 ⚙ 설정 탭에서 파일로 주고받습니다.

- **파일로 내보내기** — 모든 재생목록의 북마크를 `youtube-bookmarks-YYYY-MM-DD.json` 으로 저장
- **파일에서 가져오기** — 기존 북마크를 **지우지 않고 합칩니다**. 같은 파일을 두 번 가져와도 중복이 생기지 않습니다.

내보낸 파일에는 북마크(이름·기준 영상 ID)와 재생목록 이름만 들어갑니다.
**로그인 토큰이나 클라이언트 ID 는 포함되지 않습니다.**

### 저장 위치를 직접 찾고 싶다면

```
%LOCALAPPDATA%\Microsoft\Edge\User Data\<프로필>\Local Extension Settings\<확장ID>
%LOCALAPPDATA%\Google\Chrome\User Data\<프로필>\Local Extension Settings\<확장ID>
```

`<프로필>` 은 계정마다 `Default` 이거나 `Profile 1`, `Profile 2` … 로 다릅니다.
확장에서는 어느 프로필로 실행 중인지 알 수 없어 직접 찾아야 합니다.
안의 파일은 LevelDB 형식이라 **열어도 읽을 수 없습니다** — 백업은 내보내기를 쓰세요.

### 드라이브에 올라갔는지 확인

동기화용 파일은 앱 전용 폴더에 있어 드라이브 화면에 나타나지 않습니다.
⚙ 설정 탭에서 확인할 수 있습니다.

- **파일 확인** — 파일 이름·크기·마지막 수정 시각 표시
- **내용 열기** — 드라이브에 저장된 JSON 을 새 탭에서 보기
- **드라이브 앱 관리** — 드라이브 설정 페이지(앱 관리에서 데이터 삭제 가능)

## 다른 사람에게 배포할 때

이 확장은 **각 사용자가 본인 구글 API 를 넣어 쓰는 구조**입니다.

`manifest.json` 에는 **클라이언트 ID 항목 자체가 없습니다.** 개인 정보가 들어 있지 않으니
폴더를 그대로 압축해 배포해도 됩니다. 각 사용자는 ⚙ 설정 탭에서 본인 클라이언트 ID 를 넣습니다.

> `oauth2` 키를 manifest 에 다시 넣지 마세요. 그건 크롬 전용 `getAuthToken` 방식용이고,
> 이 확장은 엣지에서도 되는 `launchWebAuthFlow` 를 씁니다.
> 특히 `"client_id": ""` 처럼 빈 값을 넣으면 **확장이 아예 로드되지 않습니다**
> (`Invalid value for 'oauth2.client_id'`).

> 본인이 쓸 때도 마찬가지로 ⚙ 설정 탭에 클라이언트 ID 를 넣으세요.
> 설정 탭 값은 `chrome.storage.local` 에만 저장되고 확장 파일에는 기록되지 않습니다.

`manifest.json` 의 `key` 필드는 **그대로 두세요.** 이건 비밀키가 아니라 **공개키**이며,
확장 ID를 고정해서 모든 사용자가 동일한 리디렉션 URI 를 쓰게 해 줍니다(안내가 단순해짐).

> 참고: 구글 OAuth 검증을 받지 않은 앱이므로 사용자에게 "확인되지 않은 앱" 경고가
> 표시됩니다. 본인 프로젝트에서 본인이 테스트 사용자이므로 `고급 → 계속`으로 진행하면 됩니다.

## 성능 설계 (건드리면 안 되는 원칙)

긴 재생목록에서 무한 로딩·렉이 나던 문제를 해결하며 정해진 규칙입니다.

1. **유튜브 재생목록 DOM 에 쓰지 않는다.** 영상 항목에 노드를 넣거나 속성을 붙이면
   유튜브의 lazy-load 와 충돌해 무한 로딩이 발생합니다. 확장 UI 는 전부 별도 레이어
   (패널·플로팅 도구막대·모달)에 그립니다.
2. **재생목록을 상시 감시하지 않는다.** MutationObserver 로 목록을 지켜보지 않습니다.
3. **평소에 DOM 을 읽지 않는다.** 패널은 저장된 데이터만으로 그립니다.
   목록 조회는 점프·`▲▼` 처럼 **클릭했을 때만 1회**.
4. **`getBoundingClientRect` 를 반복 호출하지 않는다.** 강제 레이아웃이 잔렉의 원인이라,
   도구막대 위치는 마우스가 다른 영상으로 넘어갈 때만 1회 측정합니다.
5. **네트워크 동기화는 묶어서 보낸다.** 북마크 변경 후 3초 debounce.

이 원칙을 어기는 기능(재생목록 안에 그리는 인라인 구분선, 드래그 앤 드롭,
실시간 곡 수 카운트)은 렉을 되살립니다.

## 저장되는 데이터

전부 브라우저 로컬(`chrome.storage.local`)에 저장되며, 동기화를 켠 경우에만
사용자 본인의 구글 드라이브에 사본이 생깁니다. 외부 서버로 나가는 데이터는 없습니다.

| 키 | 내용 |
|---|---|
| `pl:<재생목록ID>` | 그 재생목록의 북마크 목록 |
| `ytpd:clientId` | 사용자가 입력한 OAuth 클라이언트 ID |
| `ytpd:sync` | 동기화 사용 여부 |
| `ytpd:enabled` | 확장 켜기/끄기 |
| `ytpd:panelPos` | 패널 위치 |
| `oauthToken` | 액세스 토큰 캐시 (1시간) |
